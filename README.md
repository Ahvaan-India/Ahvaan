# Ahvaan · Heat Intelligence Platform

Ahvaan is a zone-level heat intelligence platform covering **2563 census zones across 3 districts** (Kolkata · Haora · North 24 Parganas, 5877 forecast heatpoints). The platform renders raw backend forecasts (temperature, humidity, wind, solar, rainfall) plus backend-computed vulnerability on an interactive fullscreen map. **There is no local calculation engine** — all indices arrive precomputed from the backend service (`forecast` + `analysis` Postgres tables); this project reads them.

---

## 🌟 What We Built & Core Platform Features

1. **Interactive Zone Heat Map (`/maps`)**:
   - Fullscreen Google-Maps-style view: floating search with embedded menu, floating layers button, icon-only AI assistant, account + Send Alert actions top-right.
   - 2563 simplified zone polygons (static, generated by `npm run sync:zones`), free pan/zoom across all districts (zoom out to 0.5×).
   - Layers: HTSI, WBGT, Heat Index, UTCI, Wet-Bulb, Temperature, Humidity, Wind, Solar, Rainfall, Vulnerability — plus Location/Ward gradient view toggle.
   - Forecast time controls (live dates × 24 IST hours) driving the whole map; click any zone for its detail card with 24h curves and backend indices (hover only highlights).
   - District selector chips (other districts dim, borders outlined); summary pill scopes to the focused district.
   - GPS blue dot with automatic home-district focus; real Kolkata ward locality names; zoom-gated map labels.
   - Phone+OTP login; per-zone automated SMS ward alerts on subscribe; manual alert composer; zone-grounded AI assistant panel.

2. **District Overview (`/overview`)**:
   - Per-district zone/heatpoint counts, mean backend vulnerability, most-vulnerable-zones leaderboard linking into the map.

## 🧮 Data Model (backend-owned, no local engine)

All indices are computed by the backend service and stored in Postgres. This project only reads them:

- **Linking:** `analysis.forecast_id → forecast.id → forecast.heat_point_id`, zone via `forecast.unique_location_id` (matches `census-data.json` zones 1:1).
- **Zones:** 2563 census zones (WARD / VILLAGE / TOWN_COMBINED) with polygons + backend vulnerability (0–100) in `public/data/census-data.json`.
- **Heatpoints:** 5877 forecast tiles (1–56 per zone). No heatpoints table exists by design — tile centers are derived from zone polygons by `npm run sync:zones` into `public/data/heatpoints.json`.
- **Forecast:** 24 hourly raw-weather entries per heatpoint per date (`temperature, relativeHumidity, windSpeed, rain, shortwaveRadiation, …`).
- **Analysis:** per-forecast backend rows (empty until the backend service writes them; the map shows raw values meanwhile).

## 🏗️ Architecture & Technology Stack

- **Framework**: Next.js 15 App Router (`react` 19, TypeScript 5.7).
- **Styling & UI Design**: Vanilla CSS + Tailwind CSS (dark/light theme tokens), Framer Motion, Lucide Icons, Radix UI.
- **Data & Database**: Drizzle ORM + Postgres (`postgres-js`, read-only access to backend `forecast`/`analysis` tables).
- **Static datasets**: `npm run sync:zones` generates `public/data/{zones,manifest,districts}.json` (parsed once, kept in memory — no DB per map load). `heatpoints.json` is backend-owned; sync only validates it.
- **Auth tables**: `npm run auth:setup` creates `app_users`, `app_otp_codes`, `app_subscriptions` (the only tables this project writes).
- **Caching**: Redis is used ONLY for backend analysis payloads; everything else is process-memory cached (`lib/redis.ts`).
- **Client State & Fetching**: SWR (`useSWR`) with optimistic caching and request deduplication.
- **Login & alerts**: email+OTP sessions (signed cookies), email delivery via SMTP with logged simulated fallback; automated ward alert dispatched on every new subscription.
- **Email Notifications**: Nodemailer (SMTP with simulated fallback mode).

## 🚀 How to Run Locally

### Prerequisites
- Node.js `>= 18.0.0`
- `npm` or `pnpm`

### Installation & Execution

```bash
# 1. Clone repository & install dependencies
git clone https://github.com/vishvaaskr/SIH-Project.git
cd SIH-Project
npm install

# 2. Configure Environment Variables
cp .env.example .env
# Edit .env and supply your POSTGRES_URL (read access to backend forecast/analysis tables)

# 3. Generate the static datasets (re-run whenever forecasts/zones change)
npm run sync:zones

# 4. Create the app-owned auth tables (once per database)
npm run auth:setup

# 5. Start Development Server
npm run dev
# Open http://localhost:3000 (redirects automatically to /maps)

# 6. Type Check & Production Build
npx tsc --noEmit
npm run build
npm start
```

Phone login needs `SESSION_SECRET` in `.env`; email delivery needs
the SMTP vars — without them OTP codes are logged server-side and returned
in non-production responses (demo mode).
